# FH-02 — versión, artefacto y recuperación

5 de septiembre de 2026. **APROBADO LOCAL — madurez 3/5.** Implementación local cerrada; publicación y prueba del circuito real pendientes de FH-13. Un único revisor desde producto, técnica, datos/editorial y operación.

## Resultado

La publicación protegida ahora usa el SHA exacto que fue verificado, identifica los artefactos por ID y comprueba un manifiesto SHA-256 de todos los archivos. Rechaza cambios de contenido, archivos añadidos o ausentes, manifiestos alterados y versiones/run/attempt distintos. No depende de que `main` permanezca inmóvil durante la aprobación.

Antes de publicar requiere un ID de recuperación aprobado y lo contrasta con el despliegue canónico exitoso de producción. Después exige coincidencia entre SHA, estado, URL devuelta por Wrangler y despliegue canónico. Conserva metadatos mínimos de preflight/resultado sin copiar configuración privada. Las notificaciones opcionales sólo se habilitan tras ese registro exitoso, manteniendo su autorización separada.

El atajo local `npm run deploy:cloudflare`, que publicaba `dist` sin esta cadena, quedó deshabilitado y remite al workflow protegido. Los ZIP de `package:artifacts` continúan disponibles para revisión/respaldo, no como vía alternativa autorizada de publicación. El runbook antiguo se actualizó para evitar esa contradicción.

## Cambios concretos

- `.github/workflows/batched-deploy.yml`: checkout por SHA, outputs de identidad, manifiesto, artefactos por run/attempt e ID, comprobaciones antes de subir y publicar, recuperación y registro posterior; conserva dispatch manual, entorno protegido y serialización.
- `scripts/deploy/release-artifact.mjs`: inventario determinista, integridad exacta, rechazo de rutas inseguras/symlinks/archivos privados evidentes, identidad del checkout y manifiesto externo a `dist`.
- `scripts/deploy/release-record.mjs`: lectura acotada de Pages, validación del destino anterior y registro de la nueva publicación. No ejecuta rollback ni envía mensajes.
- `scripts/content/quality-check.mjs`: salida temporal opcional para que CI no modifique el informe versionado mientras comprueba una revisión.
- Tres archivos de pruebas cubren comportamiento del artefacto, preflight/registro y conexión de los pasos; README y runbooks explican el nuevo procedimiento.

La revisión del código distribuido de Wrangler Action encontró que instala mediante `npm i`. Para evitar cambios silenciosos de manifiesto/lock, su instalación usa `NPM_CONFIG_SAVE=false` y `NPM_CONFIG_PACKAGE_LOCK=false`; el pre-command vuelve a comprobar fuente y bytes antes de publicar. Se fijó la acción revisada en `9acf94ace14e7dc412b076f2c5c20b8ce93c79cd` y Wrangler en `4.129.0` (metadatos npm: Node ≥22, licencia MIT OR Apache-2.0). No se instaló una dependencia local ni se ejecutó Wrangler en esta entrega. La revisión integral restante de Actions/dependencias sigue en FH-04/FH-23.
